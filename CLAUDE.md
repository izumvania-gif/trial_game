# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

EFERON: The Other Hand — a desktop browser game (English only) about a time-looping Greek polis whose scribe Leont discovers he is a process in a simulation run by operators who are themselves unaware AI agents. The full design lives in `docs/concept.md` (written in Russian); read it before adding gameplay, story or visuals. Key design rules from it: each stage is a different genre with its own perspective and palette; the sea is the only non-dithered, non-deterministic thing in the game; the online counter/player lines are part of the plot and the game must keep working when the server is unreachable.

## Commands

Run from the repo root (npm workspaces: `apps/game`, `server`; Node >= 22.13).

- `npm ci` — install
- `npm run dev` + `npm run dev:server` — Vite client on :5173 (proxies `/api` to :3000) and Fastify server on :3000
- `npm run typecheck` / `npm test` / `npm run build`
- `npm start` — serve the built client and API from the compiled server (`DATA_DIR`, `PORT`, `STATIC_DIR`, `ADMIN_TOKEN` env vars; `ADMIN_TOKEN` enables `/admin` for moderating player notes)
- Single test file: `cd apps/game && node --experimental-strip-types --test test/save.test.ts` (same pattern in `server/`); single test by name: add `--test-name-pattern "wax tablet"`
- Open the game with `?debug` for the debug panel (time speed, jump to 23:58, stage jumps, "prep night" / "prep true" to skip to the board with the main or the true-ending state, export/wipe save); it also exposes the `Game` as `window.eferon`.

## Architecture

Client (`apps/game`, Vite + TypeScript + Three.js + inkjs, no UI framework — DOM via `ui/dom.ts`):
- `game.ts` is the orchestrator: owns the save, `DayClock`, `Knowledge`, `StoryEngine`, the seven stages and the modal UI (dialogue, lyre, carving, stele lines, endings). It runs dawn → day → midnight / Song of Return / ending → reset → dawn. On every reset all stages are disposed and rebuilt from a fresh `CycleState`; only `LoopMemory` survives.
- Stages (`stages/*`, interface in `stages/types.ts`) talk to the game only through `StageHost` (knowledge, memory, cycle, `notice()` for anomalies + wind, `patches()`, `loseMechanic()`, `ending()`…): `town` (third-person, vase palette, residents on schedules), `spiral` (first-person 1-bit, ring alignment + registry of past Leonts), `relief` (walk inside a frozen carving), `desk` (DOM-only operator terminal: tickets → patches), `board` (tactical night plan), `strikes` (five blows that remove mechanics), `sea` (full color), `diary` (DOM-only real-time epilogue).
- Content lives in `content/`: `knowledge.ts` (facts/sources/endings graph), `residents.ts` (schedules; `core/schedule.ts` + `core/streets.ts` resolve positions deterministically), `leonts.ts` (registry answers; `core/registry.ts` confirms three at a time), `tickets.ts` (Desk queue and patch ids), `lexicon.ts` (stele words), `endings.ts`. Patch ids decided on the Desk take effect from the next cycle and are read with `patches()` / ink `patched()`.
- `core/save.ts` — two-layer save in localStorage (`LoopMemory` vs `CycleState`), `contentVersion` = hash of the compiled story (story change → cycle state dropped, memory kept). Bump `SAVE_SCHEMA` and add a migration when `SaveFile` changes shape; new fields with defaults in `freshMemory`/`freshCycle` are filled automatically.
- `story/*.ink` (repo root) is the English script, compiled by the Vite plugin in `apps/game/vite.config.ts` via `tools/ink.ts`. Knots are entered directly (`host.interact('stele')`); every knot ends in `-> DONE`. Tags: `#speaker:X`, `#hand`, `#log`, `#hint`, `#stage:<id>`, `#spend:<min>`, `#dejavu:<id>` (+ `^` before the cue word), `#action:carve|stele_lines|board|ending:<id>`. Game-provided EXTERNALs are declared (with fallbacks) in `story/main.ink` and bound in `Game.inkFunctions()`; they are bound non-lookahead-safe so ink evaluates them only when reached (déjà vu results depend on timing).
- `render/DitherRenderer.ts` renders at 1/3 resolution and quantizes to the stage palette with Bayer dithering; palettes with `outline` also get a normals pass, and depth/normal edges are drawn in the darkest color (the incised lines). The vase palette has four tones (lacquer, added red, terracotta, bone); the board has its own `board` palette because its painted map is unlit. Anything that writes alpha 0 bypasses the dither — only the sea material (`render/sea.ts`) does, and only sea-bound things may use `seaRandom()` (the sea material, Glaucus's spot on the shore); everything else must be deterministic (`seededRng`).
- True path (docs/concept.md §4): 36 Leonts (`content/leonts.ts`), 12 shards (`content/shards.ts`, every 4 teach a stele word), the Curator's awakening on the Desk (AGENT_ID → Human Notes → the chair → directors → own USER NOTE), the double board (`core/sprint.ts`: the Curator's rollback lane during the night), `Game.trueNightMissing()` (lists unmet conditions; shown on the failed-night card), the Wake test (do not press), and the epilogue (`stages/diary`, `content/epilogue.ts`, one entry per real day). "Forget everything" keeps a `BreakShard` in `localStorage['eferon.shard']` that a new game finds (the illusion of the break). Importing a wax tablet exported during the night triggers `intermediate` (BACKUP DETECTED).
- Tests (`apps/game/test`) cover the knowledge graph reachability, ink compile + fact/action references, saves, schedules, registry confirmation and the board simulation. The `?debug` panel has "prep night" to jump straight to the board.
- Polish layer: `core/settings.ts` (per-viewer settings in `localStorage['eferon.settings']`, separate from the save; O opens `ui/SettingsPanel.ts`): volumes, sound captions, large text, déjà vu without timing, reduced motion, day length (sets `DayClock.secondsPerMinute`), quality, "less meta". `engine/audio.ts` synthesizes all sound with Web Audio (no asset files): wind driven by clock + wind, a lyre loop that detunes near midnight, a generative sea scheduled with `seaRandom`, desk hum, rain/thunder, Karplus–Strong plucks; `play(id)` also emits captions. `DitherRenderer.setQuality` + frame-time watching steps auto quality down (shadows off, then 4px pixels) and never back up. `ui/meta.ts` drives the tab title / favicon / console DEV COMMENTs unless "less meta" is on.
- Dialogue UI (`ui/Dialogue.ts`): a portrait tondo beside a separate box with a nameplate, typewriter reveal (off with reduced motion), numbered choices. Portraits are procedural black-figure busts in `ui/portraits.ts` (drawn with paths at 4×, reduced by majority vote to 72 px, painted in the current stage's palette: `vase` or `marble`); `portraitFor(#speaker)` maps speakers to them — a new `#speaker:` needs an entry there (a test checks every ink speaker). `?portraits` shows the whole sheet.
- Guides (`content/guides.ts`, `ui/Guide.ts`): a how-to card the first time the player is free in each stage (H shows it again), small tips for new mechanics (déjà vu, chronicle, book, wind, masks, the first reset); seen ids live in `LoopMemory.guides`, the `tips` setting turns them off. `STAGE_CONTROLS` feeds the bottom-left keycap bar; prompts and controls use the "KEY — label · KEY — label" format rendered by `ui/keys.ts`. Text never sits directly on a dithered view: HUD pieces are chips on `--panel`, and the CSS tokens in `style.css` keep small text at 4.5:1 or better.
- All server calls go through `src/api.ts` and must fail soft (return `null`).

Server (`server`): Fastify app built in `src/app.ts` — `/api/counter` (global CYCLE RUN), `/api/stele` (lines built only from the fixed vocabulary in `src/stele.ts`, rate-limited per IP) and `/api/notes` (free-text notes from the epilogue, filtered in `src/notes.ts` and premoderated: only admin-approved notes are ever returned; `/admin` + `/api/admin/*` exist only when `ADMIN_TOKEN` is set) (`buildApp` takes a `Store`, so tests use `openStore(':memory:')` + `app.inject`). Persistence is `node:sqlite` (built-in, no native deps) in `src/db.ts`; the DB file is `$DATA_DIR/eferon.sqlite`. The server also serves `apps/game/dist` with an SPA fallback. Server TS runs directly via Node type stripping in dev/tests (hence `.ts` import specifiers and `erasableSyntaxOnly` — no parameter properties or enums) and is compiled with `tsc` for production. The global cycle counter starts at `CYCLE_RUN_FIRST = 1472` (the prologue's cycle number).

## Deploy

Pushes to `main` run `.github/workflows/ci.yml` (typecheck, tests, build, Docker build + smoke test). Amvera builds the root `Dockerfile` per `amvera.yml` (docker environment, persistent mount `/data`, port 3000) and deploys on the GitHub "Workflow runs" trigger, so only green CI deploys. The Dockerfile copies `apps/game`, `server` and `story` explicitly — add new top-level source dirs there.
